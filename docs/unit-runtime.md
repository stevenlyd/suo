# Repository Units (schema 5)

One flat registry holds Unit objects and canonical typed references. Containment is a single-parent forest; labels carry familiar names such as module and feature without imposing levels. Decisions remain normative choices attached to Units, not automatically deliverable Units. Git owns prior definitions.

`inspect` defaults to committed HEAD. `--target index` inspects staged bytes; `--target working-tree` explicitly previews tracked and unignored new files. Neither preview is a claim about HEAD. Commit reads use Git blobs, not dirty paths. LFS pointers and gitlinks report unavailable inputs. No network fetch occurs implicitly.

The only implementation states stored are unknown, not_started, in_progress and implemented. These are declarations about the code mapping, not behavioral proof. A complete declaration needs source mappings for each criterion and each own integration obligation. Parents also require bounded scope and complete children; an open parent does not prevent a child consuming its local defined contract. Missing check policy stays null and blocks verification readiness; it never means no checks. Acceptance and provider execution results are not repository-current state.

Definition fingerprints include inherited constraints, normative decision prerequisites, and phase prerequisites, including composite child definitions when a consumer needs a parent's implementation. Input fingerprints cover all listed repository files, including configuration, lockfiles and new candidate files, except authority/generated views and explicitly declared non-runtime paths. Exclusions are a reviewed input-policy assertion, not automatically proven dependency analysis. Direct coverage into an exclusion is rejected. Do not exclude an indirect runtime input. Dynamic external inputs cannot be proven by this mechanism; unavailable source inputs prevent current applicability. A matching fingerprint proves unchanged supplied inputs, not correct behavior or authenticated authorship.

No final commit SHA is written inside its own files. Coverage stores content fingerprints; the caller supplies the commit identity. Checkout paths and optional TS/JS symbol names resolve deterministically. Symbol existence does not prove that a criterion is implemented. Changed relevant definitions or inputs make applicability stale while preserving the original declaration visibly. Duet must inspect fresh applicability before reporting completion.

JSON/API shapes reject unknown fields, missing fields, invalid references and unsafe accessor objects. TypeScript authority uses a sealed generated ontology and declarative canonical imports. Bundling consumes captured validated source text. DAG/phase cycles, multiple parents and missing edges fail with diagnostics. Finite-domain inherited constraints use reversible traversal environments; natural language constraints still require semantic review.

All owned graph, hierarchy, source-directory and canonicalization traversal uses explicit stacks or queues. Graph processing is O(V+E); sorting, hashing, input bytes and constraint intersections add their own costs. No transitive-closure matrix or copied ancestor list is built. Third-party TypeScript/esbuild internals are not claimed to be stack-free. The persisted structure is flat, so logical nesting does not force nested syntax or JSON.

Writes require the observed full repository content token. Candidate source is staged and validated before replacing the authority. A project lock serializes cooperating writers. A journal makes crash recovery explicit; working-tree reads reject a pending transaction, while immutable commit/index reads remain available. Conflicting/corrupt backups are preserved without restoring them. A process crash can leave the lock; verify that no writer is alive before manually removing that lock. Git and an external editor are not controlled by the lock: inspect/review the final diff and use normal Git conflict/CI flow.

Duet collects current CI, PR and deployment observations outside Suo. A generated runtime manifest identifies the artifact serving a response at observation time, separately for independently deployed components. Never persist `deployed`, `CI green`, branch inclusion or an old external authorization as current Suo knowledge. A reference in a document does not authenticate its provider or prove present applicability.
