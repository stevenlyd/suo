# Upgrade to current-state authority (0.7)

Source schema 4 and compiled schema 3 deliberately replace the historical model. Preserve the old checkout in Git or a backup; do not weaken validation or retain a parallel legacy authority.

1. Inspect each branch independently. Carry forward its current effective goals, contracts, relevant decisions, unresolved questions and typed dependencies. Do not infer official scope from code or promote experiments during conversion.
2. Drop decided proposal audits and historical handoff generations from current authority. Remove superseded decisions only after resolving references to the actual current decision; ambiguous relationships need completion. Do not reconstruct old counters or contract bodies. Git retains them.
3. Preserve genuine current check policy if present. If it is unknown, explicitly set both `requiredChecks` and `checkRationale` to `null` and keep the module shaping. Never interpret unknown as an empty list. Complete the policy through the real authorized Product decision before freeze/acceptance.
4. Create at most one current handoff per ready module, using current definition identity. Prior implementation/acceptance evidence can remain only with the definition digest and implementation identity it actually assessed; mark mismatches stale. Do not infer acceptance from merge/CI or stamp old evidence with a new digest. With no recorded delivery evidence, leave realizations/closures empty.
5. Write into an isolated candidate directory, validate with `suo diagnose` and source `suo check`, and inspect the generated projections and branch diff. Use normal review and Git flow before adopting. This is not deployment authorization.

Pending proposal envelopes require the observed local concurrency token `expectedRevision`; the token is not Git history or cross-branch identity. API/save paths reject stale observed content and use recoverable commits to consume local staging without resurrecting approvals. Interrupted `.suo/commit.json` transactions must be resolved, not discarded. Vault uses `suo-state/current.json` and a temporary transaction journal; old history files are not required by the new adapter. Convert a Vault in isolation using its current notes and lifecycle state, then use native adoption/review; keep unrelated notes intact.

Strict schema, discriminated operations, canonical typed imports, unique IDs, dependency DAG checks and meaningful passing evidence remain mandatory. Evidence is supplied, not provider-authenticated. User names are declared identities. A separate policy layer or approval-history migration is unnecessary.
